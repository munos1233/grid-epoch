# 衍枢值班台前端修改方案

本文只规定值班台页面怎么改。改完之后，同一套操作的截图在页眉上能分开；右栏表单、配色和左右分栏保持原样。

## 预期差别

评委翻页时，眼睛停在页眉。现在每次操作的结论是右栏底部 14px 的一行，缩进报告后看不见，于是 21 张图像同一页。

改完以后：

- 每次操作的结论出现在四盏灯正下方，22px，浅色。未发布、发布、错口令、确认、扣下、吊销、换表、割接、销毁、召回，第一眼就是不同的句子。
- 割接到台区 45 后，左侧同一页出现 45，终端表切到新序号。现在新台区在分页后面，终端表仍停在旧台区。
- 覆盖灯写「当前吊销集的覆盖」。终端报文、网关报文、吊销根三盏写「最近一次发布」。吊销或召回之后，覆盖灯可以变成「子集差」，三盏字节灯仍是上一份发布的长度，两套数字不再挤在同一组灯里让人读成「子集差报文还是 236 字节」。

右栏的输入框和按钮仍在。口令、托管、接入核验、观察名单、吊销网关、重新灌装这些操作，台区表往往不动，全页窗口仍然相似。报告和幻灯片里，这几张裁到「页眉 + 结果条」；表格真的变了的步骤才用全页。本次不要为了让全页更不一样去换皮肤。

## 允许改的文件

- `grid_epoch/console.html`
- `grid_epoch/console.py`：仅 `/api/zones` 增加可选查询参数 `size`

不要改协议、密码运算、`desk.py` 的默认分页、测试所依赖的接口字段、报告和已有截图。

## 1. 结果条

把现有 `#result` 从右栏挪到 `header.bus` 内、`.bus-row` 之下，占满页眉宽度。

- 字号 22px，浅色（`#f4faf7`），`white-space: pre-wrap`，至少一行高。
- 页面初次打开、尚未操作时，文字为「尚无操作」。
- 成功与失败都只写这一个节点。失败时给结果条加一条左侧故障色边，不要把整页变红。成功时去掉这条边。
- `refresh()` 不得清空结果条。台区号输入变化触发的刷新也一样。
- 右栏原位置不再保留第二份结果。

元素 id 保持 `result`。现有 `run()`、各按钮的 `onclick` 继续写 `result.textContent`。

各操作的句子如下。未列出的保持 `console.html` 里的现有句子。

| 操作 | 结果条 |
|---|---|
| 核对两份口令成功 | 两份口令核对通过 |
| 口令或其它操作失败 | 使用接口返回的错误句，不改写 |
| 恢复纪元托管 | 纪元 N 的托管包已打开，随机数未显示 |
| 丢弃过期随机数 | 已丢弃纪元 N 之前的随机数，当前纪元仍为 N |
| 接入核验成功 | 接入签名核对通过，纪元仍为 N |
| 吊销网关 | 已吊销台区 Z 的网关，管控密钥未轮换 |
| 重新灌装 | 已重新灌装台区 Z 序号 L，管理种子与原先一致 |
| 换表 | 已换到序号 L，叶子 X。旧序号已吊销 |
| 观察名单、核对确认、发布、吊销、销毁、归档、召回 | 保持现有句子 |

纪元 N 用当时页眉上已经显示的纪元数字。接入核验的返回体没有纪元字段，不要为这一句改接口。恢复纪元托管的返回体保持 `{ok, epoch}`，页面上不出现随机数、分片或主密钥。重新灌装的句子只陈述「与原先一致」，不显示种子。

本地校验失败、尚未发请求的句子也写进同一条结果，并带故障色边：

- 纪元号为空或非法：「请填写要打开的纪元」
- 固件版本为空或非法：「请填写要召回的固件版本」
- 没有更早的审计：「没有更早的审计」

## 2. 四盏灯

覆盖灯副标题维持「当前吊销集的覆盖」。

终端报文、网关报文、吊销根三盏，有报文时副标题改为：

`最近一次发布 · {字节数} 字节 · SM2 通过`

验签失败时，把「通过」换成「失败」，灯的失败样式保持现有 `.bad`。没有报文时仍是「还没有这一份」。

不要按当前吊销集重算包长，不要再加一段说明文字。页脚的本机吞吐句子保持现在的 `load_bench()` 口径，不要改成另一轮测量。

## 3. 台区表一次能看见割接后的新台区

`grid_epoch/console.py` 的 `/api/zones` 读取查询参数 `size`：

- 缺省 2，与现在 `desk.zones` 的默认参数一致。
- 只接受整数。小于 1 按 1，大于 8 按 8。
- 把这个值传给 `desk.zones(page, size)`。
- 不修改 `desk.zones` 的默认参数。现有测试继续以每页 2 条调用。

`console.html` 请求台区时带 `size=8`。演示里的台区（42、43、44，以及割接产生的 45）落在同一页，页码为 `1 / 1`。

分页按钮从终端表下方移到台区表下方，旁边标明「台区」。终端表不分页。台区不超过 8 个时不需要翻页；按钮逻辑可以保留。

## 4. 割接和换表之后，左侧表跟过去

`run()` 的顺序是：写结果条，调用 `summarize`，再 `refresh()`。`refresh()` 用台区号输入决定终端表。因此在 `summarize` 里改输入，刷新就会显示新表。

- 割接成功：把台区号输入设为返回体里的新台区，序号输入设为新序号，然后再刷新。结果条保持「已割接到台区 Z 序号 L」。左侧台区表出现新台区，终端表是新台区的那一行。
- 换表成功：台区号不动，序号输入改为新序号，然后再刷新。终端表同时看得到已吊销的旧序号和新叶子。

不要为了这一步新增接口字段。

## 5. 明确不做

- 不改配色、字体、页眉渐变、左右栏比例、按钮清单和按钮文案。
- 不加图表、动画、新页面。
- 不显示主密钥、种子、随机数、分片、签名或报文十六进制。
- 不加「观察」列。尚未收到报文的台区继续显示「未下发」。观察名单只出现在结果条的现有句子里。
- 不为「查询已销毁」增加区域。销毁成功后，终端行变为「已销毁」，结果条写明叶子保留。
- 不改 `console.py` 读入 HTML 的方式。`PAGE` 在进程启动时读入，改完必须重启 `make console`。

## 6. 验收

重启值班台后再看页面。然后跑 `make test`，应全部通过。

1. 刚打开：结果条在四盏灯下方，文字是「尚无操作」。右栏按钮下方没有另一行结果。
2. 发布纪元 1：结果条为「已发布纪元 1」。三盏报文灯带「最近一次发布」。覆盖灯是「完全子树」。
3. 错误口令：结果条为接口的失败句，并有左侧故障色边。台区表与终端表不变。
4. 两份口令核对通过；恢复纪元托管的结果条含「随机数未显示」，页面其它位置没有随机数；丢弃过期随机数的结果条含「当前纪元仍为」当时的纪元；接入核验的结果条含「纪元仍为」同一数字。
5. 扣下序号 1：结果条写明完成帧被拒绝、所缺序号、已吊销仍为 0。该终端行是「被扣下」。
6. 吊销该序号：结果条写明已吊销。覆盖灯变为「子集差」。三盏报文灯仍标「最近一次发布」，字节数可以仍是上一份发布的长度。
7. 换表：终端表出现新序号；结果条含新叶子，并写明旧序号已吊销。
8. 割接到 45：不用按下一页。台区表同一页有 45。终端表是新台区的新序号。
9. 销毁：该行变为「已销毁」，结果条写明叶子保留。
10. 吊销网关、重新灌装：结果条分别含「管控密钥未轮换」「管理种子与原先一致」。页面上没有密钥材料。
