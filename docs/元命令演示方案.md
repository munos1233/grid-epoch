# 衍枢连贯元命令方案

把现在塞在 `make demo` 里的整段故事拆成可以单独截图的命令。命令仍是一条时间线：后一步的前提就是前一步的结果。现场连讲用一条命令按顺序把全部步骤打出来。

这次只加演示入口。不改值班台页面，不改 `demo.py` 和 `split_demo.py` 的现有输出，不改报告里的测试计数和基准数字。

## 评委看到的连贯

角色固定，顺序固定。

- 台区 42 序号 0：认证、电能量、控制、重新灌装都用它。
- 序号 1：被扣下的那一台，确认交齐后，再割到台区 45 序号 5。
- 序号 2：被吊销，随后换成新序号 4。
- 序号 3：发布纪元 1 时不把报文交给它。漏收之后直接进入纪元 2。最后销毁的是它。
- 台区 43：已经登记，始终不收报文，用来显示观察名单。
- 树的规模沿用现有演示的 16 叶。字节数以当次输出为准。不要写成报告里那一轮实测的 236 / 216 / 118。完成帧长度仍是协议里的 62 字节。

每一步打印的第一行都是承接，例如：

```text
承接  纪元 1  台区 42 在册 3 台已收到报文  序号 3 仍在纪元 0  台区 43 未收到  吊销集为空
```

后面三到六行只写这一步的结论。截到任何一张，都能看见它接在哪一步后面。

`make scenes` 在一个进程里按下面的顺序把每一步都打印出来，给五分钟连讲用。单独截某一步时：

```bash
.venv/bin/python -m grid_epoch.scenes jump
```

进程仍先执行同一批前面的步骤，只是不打印，然后打印这一步的承接和结论。因此单独截图和连讲走到这一步是同一个状态，不会另起一套初始条件。不把主站对象存进目录，避免半截纪元留在磁盘上。

不提供跳步。召回放在最后，因为它把整批放进吊销集，放前面会把后面还要用的在册终端清掉。

## 允许改的文件

## 命令

口令与值班台相同：值班甲、值班乙。输出不回显口令，不打印主密钥、种子、随机数、分片、路径密钥和签名十六进制。

| 顺序 | 命令 | 承接里要能看见 | 这一步的结论 |
|---|---|---|---|
| 1 | `init` | 尚无纪元 | 区域、台区 42 序号 0–3、台区 43 已登记。纪元 0。四台在册。吊销集为空。固件版本已标为 1，这一步不召回 |
| 2 | `epoch0` | 纪元 0，序号 0 在册 | 序号 0 做业务被拒绝 |
| 3 | `publish` | 纪元 0 | 进入纪元 1。终端报文、网关报文、吊销根的字节数，SM2 通过，覆盖为完全子树。序号 0、1、2 进入纪元 1。序号 3 仍在纪元 0。台区 43 未收到 |
| 4 | `auth` | 纪元 1，序号 0 已进入 | 序号 0 认证通过 |
| 5 | `energy` | 纪元 1，序号 0 已认证 | 主站解开电能量明文。台区派生业务密钥被拒绝 |
| 6 | `control` | 纪元 1 | 台区打开控制报文。主站也能打开 |
| 7 | `passwords` | 纪元仍为 1 | 一份口令失败。两份口令通过 |
| 8 | `escrow` | 纪元 1 的托管还在 | 纪元 1 的托管已打开。随机数未显示 |
| 9 | `enroll` | 纪元 1，序号 0 在册 | 序号 0 的 SM9 接入通过。纪元仍为 1 |
| 10 | `watch` | 台区 42 已收到纪元 1，台区 43 未收到 | 观察名单是台区 43。未收到报文，不参与验签，也不是确认失败 |
| 11 | `jump` | 序号 3 仍在纪元 0，其余已在纪元 1 | 发布后序号 3 直接进入纪元 2。把纪元 1 的旧报文交给它，被拒绝。序号 0、1、2 也进入纪元 2 |
| 12 | `drop` | 当前纪元 2，纪元 1 曾经有托管 | 纪元 2 之前的随机数已丢弃。当前纪元仍为 2。再打开纪元 1 的托管失败 |
| 13 | `withhold` | 纪元 2，四台都能收当前报文，吊销集为空 | 扣下序号 1，完成帧被拒绝。缺的是序号 1。吊销数仍为 0 |
| 14 | `confirm` | 上一帧被拒绝，吊销数仍为 0 | 四台交齐。完成帧 62 字节 |
| 15 | `revoke` | 序号 2 在册，当前纪元已确认过 | 吊销序号 2 并发布新纪元。序号 2 解不开。序号 0、1、3 和新纪元对齐。覆盖为子集差，并打印子集条数 |
| 16 | `replace` | 序号 2 已吊销 | 新序号 4 进入当前纪元，打印新叶子。序号 2 仍解不开。序号 0 沿用灌装时的路径密钥进入同一纪元。这一步内部可以发布一次，承接行写发布后的纪元 |
| 17 | `transfer` | 序号 1 在册，台区 45 尚未出现 | 序号 1 割到台区 45 序号 5。旧叶子拒绝。新序号进入当前纪元。需要的发布写在这一步内部 |
| 18 | `gateway` | 台区 42 仍有在册终端 | 台区 42 的网关槽作废。台区管控密钥未轮换 |
| 19 | `reprovision` | 序号 0 在册且未销毁 | 序号 0 重新灌装。管理种子与原先一致 |
| 20 | `destroy` | 序号 3 在册，叶子号已知 | 序号 3 档案已销毁。打印叶子号并写明保留。吊销集不因此加入这片叶子 |
| 21 | `reject-enroll` | 序号 3 已销毁，叶子保留 | 接入核验失败 |
| 22 | `reject-transfer` | 序号 3 已销毁 | 割接被拒绝 |
| 23 | `reject-reprovision` | 序号 3 已销毁 | 重新灌装被拒绝 |
| 24 | `recall` | 台区 42 固件版本为 1，此前销毁未把叶子放进吊销集 | 召回固件 1。打印摘掉的批次数和子集差条数 |

换表、割接里如果终端必须先拿到新报文才能进入纪元，沿用 `demo.py` 的做法，在该命令内部发布并交付。不要再拆一条只有「发布成功」的命令。

## 实现约定

- 步骤是 `scenes.py` 里的一组函数，按上表顺序放在一个元组里。`run` 和单步命令都走这个元组。
- 单步命令按名字找到位置，前面的函数执行但不打印，当前函数打印。
- 名字未知、或写成被禁止的跳步时，退出码非 0，并打印可用名字。
- 断言失败时退出码非 0。不要捕获之后仍打印成功句子。
- 电能量用现有 GE01 路径，控制用现有 GE03 路径。台区打开控制用现有 `open_control`。台区派生业务密钥应得到现有的拒绝。
- 扣下完成帧沿用 `demo.py` 里伪造 ZALL、主站拒绝、再定位缺台的做法。交齐时用网关生成的完成帧，长度为 62。
- 换表后比较序号 0 的路径密钥与灌装时相同，只打印「沿用」，不打印密钥。
- 重新灌装前后在内存里比较管理种子，只打印「一致」。
- 吊销网关前后在内存里比较台区管控密钥，只打印「未轮换」。
- 销毁后的三种拒绝调用现有销毁检查，不新增错误种类。
- `Makefile` 增加：

```make
scenes:
	$(PY) -m grid_epoch.scenes run
```

连讲是 `make scenes`。单步是 `python -m grid_epoch.scenes <名字>`，名字与表中命令列相同。

## 测试

在 `tests/test_grid_epoch.py` 增加一条测试：按顺序调用全部步骤函数，断言下列结论。

- 纪元 0 拒绝业务
- 台区派生业务密钥被拒绝，主站能解开电能量，台区能打开控制
- 序号 3 漏掉纪元 1 后进入纪元 2，旧报文被拒绝
- 丢弃之后当前纪元不变，纪元 1 的托管打不开
- 扣下后吊销数不变；交齐后的完成帧为 62 字节
- 吊销后序号 2 解不开，覆盖为子集差
- 换表后新序号进入，序号 0 的路径密钥与灌装时相同
- 销毁后的叶子不在吊销集里，接入、割接、重新灌装都被拒绝
- 网关更换前后台区管控密钥相同
- 召回的覆盖为子集差

不比较整段打印文本。不要把报告里的「43 项」改成新的总数。
